# MarkAuto 正式產品化優化計畫（P0–P2）

> 建立：2026-10-17。依據：main `f988241` 的三輪唯讀分析：第一輪為空白狀態的 1366×768 離屏截圖、GitNexus 圖譜與原始碼量測；第二輪在隔離暫存工作區建立示範資料、實際跑完回測後截圖，另做效能量測、死碼檢查，並檢視安裝程式與日誌隱私；第三輪實際操作紙上交易、Walk-forward 與官方資料下載。
> 用途：交給 AIWorkflow 逐項實作與驗收。本文件只列「既有功能的優化與修正」；**新功能擴充不在範圍內**，全部完成後另行討論。

---

## 0. 目標

把 MarkAuto 從「工程驗收工具」的樣子，改成一般使用者能直覺操作的正式桌面產品：

1. 畫面乾淨：預設只看到完成工作需要的欄位，不出現工程用語、重複警語、原始例外訊息。
2. 操作直覺：每頁有清楚的主要動作、明確的流程順序、有標籤與單位的欄位。
3. 程式可維護：拆掉巨型類別與循環依賴，集中樣式與文字，讓後續擴充便宜。

---

## 1. 不可破壞的規則（每一項都適用）

這些是專案既有的安全與溯源保證。任何一項變動若違反，該項驗收直接不通過。

| # | 規則 | 說明 |
|---|---|---|
| G1 | **實盤固定停用** | 不新增任何券商連線、下單或實盤開關。 |
| G2 | **失敗即封鎖（fail-closed）不放寬** | 驗證、拒絕條件、額度與一次性 OOS 消耗規則一律不變；UI 只能改「怎麼呈現」，不能改「是否允許」。 |
| G3 | **溯源鎖定檔案** | 下列 8 個檔案的 SHA-256 被寫進 `quantlab/saved_candidate_pool.py` 的 producer profile：`quantlab/research.py`、`quantlab/provider.py`、`quantlab/core.py`、`quantlab/strategies.py`、`quantlab/backtest.py`、`quantlab/data.py`、`desktop_chatgpt_auth.py`、`desktop_chatgpt_provider.py`。**連格式化都會改變 hash。** 必須修改時：只能「追加」新 profile，既有 profile、hash、選擇邏輯一律不動，並補新舊來源各自選回原身分的回歸測試（比照 PR #24、#29、#31 的做法）。能不碰就不碰。 |
| G4 | **研究模組匯入邊界** | `tools/quality_gate.py` 禁止研究模組匯入 `trader`、`shioaji`、`pickle`、`subprocess` 及呼叫 `eval/exec/compile/__import__`。搬移檔案後仍需通過。 |
| G5 | **不降低測試** | 不刪測試、不放寬逾時、不以 mock 取代原本的真實路徑、不 skip。UI 文案改了，對應測試在同一個 PR 內一起更新。 |
| G6 | **規格文件同步** | 行為或文案若被 `docs/agent/IMPLEMENTATION_CONTRACTS.md`、`docs/agent/ACCEPTANCE.json` 引用，同一個 PR 內一起更新並說明原因。 |
| G7 | **GitNexus 流程** | 依 `AGENTS.md`：編輯符號前跑 `impact`，commit 前跑 `detect_changes`；HIGH/CRITICAL 風險要先說明。圖譜「無影響」不能取代測試。 |
| G8 | **CI 重跑方式** | Quantlab 彙總檢查只接受同一輪 attempt 的證據；需要重跑時用「重跑全部 job」，不要只重跑失敗的 job。 |

- 程式修改 + 對應測試新增或更新，`python -m unittest discover -s tests` 在 Windows 通過（既有平台 skip 除外）。
- `tools/quality_gate.py` 通過。
- UI 類項目：用 P0-00 的截圖工具產生前後對照截圖與量測數字，附在 PR。
- PR 說明寫清楚：改了什麼、為什麼、驗收數字、未驗證的部分。

## 3. 建議執行順序

```
P0（快速修正，含真實 bug）
  → P2-A（架構地基：文字表、主題、頁面拆分）
    → P1（體驗重整，建在新的頁面元件上）
      → P2-B（其餘架構整理）
```

理由：P1 要大改頁面版面。若先在 2,365 行的 `desktop_ui.py` 上改，P2 拆檔時要再搬一次。先做 P2-A 的地基，P1 只改一次。每個方塊內的項目可以各自一個 PR；同一批次內互不依賴的項目可以平行。

## P0 — 快速修正（約 4–6 天）

### P0-00 UI 截圖與量測工具
- **問題**：UI 優化沒有可重現的量測方式，驗收只能靠主觀判斷。
- **改法**：新增 `tools/ui_snapshot.py`。在隔離暫存工作區建立 `MainWindow`，依序切換每頁，輸出：每頁的視窗截圖與整頁截圖 PNG，以及 JSON（頁面高度、可見輸入欄數、按鈕數、標籤字數、所有可見文字、沒有標籤的輸入欄清單、主要按鈕數）。支援 `--size 1366x768`、`--scale 1.5`（模擬高 DPI）。不得讀寫使用者真實工作區。
- **驗收**：在乾淨環境執行輸出與第 2 節同格式的數字；附一個測試確認工具只使用暫存目錄。

### P0-01 畫面刷新會讓紙上帳戶「需要對帳」（真實 bug）
- **問題**：每個背景作業完成後，畫面會刷新紙上帳戶卡片（[desktop_ui.py:1890](../../desktop_ui.py)，`_show_account(_paper(self.root).snapshot())`）。`_paper()` 每次都建立新的 `PaperBroker`，而 `PaperBroker` 開啟既有帳本時一定會寫入一筆 `restart` 事件（[quantlab/paper.py:270-271](../../quantlab/paper.py)）；`restart` 會把帳戶設成「需要對帳」（[quantlab/paper.py:226-227](../../quantlab/paper.py)）。
  - 實測（隔離暫存工作區）：按「明確對帳紙上帳戶」後，作業結果的帳戶狀態是 `reconciliation_required: false`，但畫面卡片立刻顯示「需要對帳：是」。
  - 帳本出現使用者沒有做過的 `restart` 紀錄（例如對帳前就有 `restart:1`、`restart:2`），稽核紀錄失真。
- **改法**：為「只讀顯示」提供不寫入事件的唯讀快照路徑（例如 `PaperBroker.read_snapshot()` 或唯讀開啟模式），畫面刷新改用它；`restart` 事件只在真正的程式啟動或 worker 接手時寫入。`quantlab/paper.py` 不是 G3 鎖定檔。重啟後必須對帳的安全規則不變（G2）。
- **驗收**：
  - 新增測試：對帳後連續刷新畫面 N 次，帳本事件數不變，帳戶仍是「不需要對帳」。
  - 真正重啟程式後仍要求對帳（既有測試通過）。
  - `tests/test_paper*.py`、`tests/test_desktop_ui*.py` 全數通過。

### P0-02 按鈕分三級
- **問題**：所有按鈕同樣藍色、整排滿版；「緊急停止」與「新增一列」看起來一樣。
- **改法**：在樣式中定義 `primary`（實心藍，每頁最多 1 個）、`secondary`（外框）、`danger`（紅色：緊急停止、還原備份、取消委託、刪除）。`_button()` 增加 `role` 參數。按鈕寬度依內容，同一列並排，不再整排滿版。危險動作一律二次確認（既有確認機制保留）。
- **驗收**：截圖工具顯示每頁 primary ≤ 1；`danger` 按鈕清單與上列一致；既有按鈕 objectName 不變（測試靠它找按鈕）。

### P0-03 欄位標籤與單位
- **問題**：資料頁的 `960`、`1`，紙上交易頁的 `100`，以及回測頁、AI 頁數個空白下拉選單，旁邊沒有標籤。
- **改法**：每個輸入元件都有可見標籤；數值欄位用 `QSpinBox` 的 suffix 標示單位（根、日、筆、秒、TWD、點）。
- **驗收**：截圖工具的「沒有標籤的輸入欄」清單為空。

### P0-04 修正頁面名稱與截斷
- **問題**：
  - 回測頁寫「使用『策略與版本』目前選定…」（[desktop_ui.py:1125](../../desktop_ui.py)），但側邊欄沒有這一頁，它叫「AI 策略中心」。README 的 Walk-forward 段落也引用「策略與版本」。
  - 紙上交易頁兩個表格的表頭被截斷（「始 UTC」「結束 UTC」「交易E」）。
- **改法**：統一頁面名稱；表格欄寬依表頭自動調整，或改用可換行的表頭；README 同步。
- **驗收**：全專案搜尋不到已不存在的頁面名稱；截圖中表頭完整可讀。

### P0-05 使用者看得懂的錯誤訊息
- **問題**：`MainWindow._safe`（[desktop_ui.py:1473](../../desktop_ui.py)）把 `str(exc)` 直接放進狀態列；desktop_ui 共 7 處、desktop_market 3 處、desktop_chatgpt_ui 1 處顯示原始例外文字。
- **改法**：建立錯誤代碼對照表（代碼 → 中文說明 → 建議動作）。狀態列只顯示中文說明與建議；「詳細資訊」展開後只顯示錯誤代碼與發生階段。**不得把原始例外文字寫進日誌**：既有 `RedactedEventLog`（[quantlab/desktop_runtime.py:466](../../quantlab/desktop_runtime.py)）只接受固定的操作與事件代碼，這個隱私設計要保留；若要記錄錯誤，只能新增固定的錯誤代碼欄位。不得顯示金鑰、路徑、token、回應內容。
- **驗收**：新增測試餵入各類已知例外，狀態列文字都來自對照表；未知例外顯示通用中文訊息加錯誤代碼。

### P0-06 啟動失敗訊息說出原因
- **問題**：[desktop.py:865](../../desktop.py) 一律只顯示「RuntimeSafetyError: startup failed」。本次實測的真因是 SQLite 3.50.4 低於工作區要求的 3.51.3，使用者完全看不出來。
- **改法**：對已知、不含機密的 `RuntimeSafetyError` 類別，顯示中文原因與下一步，例如「此工作區需要較新的 SQLite 執行環境，請改用正式安裝版」或「工作區格式較新，請安裝相容版本」。未知例外維持現有通用訊息。
- **驗收**：測試涵蓋 SQLite 版本不足、工作區格式不相容、工作區被占用三種情境，各自顯示正確中文訊息；訊息不含例外原文中的路徑。

### P0-07 安全警語合併成單一狀態標記
- **問題**：「唯讀」「實盤停用」同時出現在頂部橫幅、頁首、內文；市場總覽有三處「主程式未提供」；每頁都有長段免責聲明。
- **改法**：頂部保留一個精簡狀態標記，例如「🔒 研究模式・實盤停用」，點擊展開完整說明。各頁移除重複警語，只在「真正要做出不可逆動作」的地方保留必要提醒（例如 OOS 一次性消耗同意框）。
- **驗收**：預設狀態下，每頁可見文字中「實盤」「唯讀」相關字樣合計 ≤ 1 處（頂部標記除外）；法遵必要的說明仍可在展開內容中找到。

### P0-08 進階內容預設收起
- **問題**：每頁都露出「進階診斷 JSON（一般操作不需要）」勾選框；AI 頁同時攤開三大區塊。
- **改法**：各頁的進階診斷、完整來源證據、技術參數統一收進可展開的「進階」區塊，預設收起，展開狀態記憶在使用者偏好（非敏感設定）。
- **驗收**：預設狀態下 AI 策略中心高度 ≤ 1,600 px（約 2 個螢幕）；紙上交易與復原 ≤ 1,600 px。

### P0-09 ChatGPT 登入的兩個收尾
- **問題**：
  - `desktop_chatgpt_ui.py:22` 的 `LOCAL_ACTIONS` 註解寫「只讀本機」，但 `restore` 可能連網 refresh，因此跳過了「先等背景作業停止」的保護。目前只在背景閒置時觸發，實際無害，但分類錯誤，未來容易誤用。
  - `desktop_chatgpt_ui.py:626` 的 refresh 失敗被 `except Exception: pass` 吞掉，沒有任何紀錄（`:667` 同樣模式也一併檢查）。
- **改法**：`restore` 另立分類（「可能連網、但只在閒置時由主程式排程」），註解據實描述；失敗時記錄固定的階段代碼（不含 token、不含例外原文，遵守 `RedactedEventLog` 只收固定代碼的規則）。
- **驗收**：既有 71 個 ChatGPT UI／整合測試通過；新增測試確認 refresh 失敗會留下階段代碼、畫面恢復顯示登入按鈕。

> 以下 P0-10 ～ P0-16 為第二輪分析（載入示範資料並實際跑完回測後）新增。

### P0-10 數字格式化
- **問題**：回測結果直接印出未格式化的浮點數，例如「最大回撤（比例）：0.0017810631607774310712565190709 68670」「夏普值（描述性）：-7.98249664979112245085…」（30 位小數）；比例以小數顯示（報酬率 -0.000706、勝率 0）而非百分比；金額沒有千分位（1000000、999294）。
- **改法**：統一數字格式函式：金額 `1,000,000 TWD`、比例 `-0.07%`、指標 2 位小數、點數整數。只改「顯示」，內部值、儲存值與 hash 不變。
- **驗收**：預設畫面中沒有超過 4 位小數的數字；比例一律以 % 顯示；有測試確認顯示格式與內部值分離。

### P0-11 英文狀態代碼改中文
- **問題**：資料頁顯示「資料來源：SYNTHETIC」「實單：DISABLED；真實模型：NOT_VERIFIED」，直接露出內部列舉值。
- **改法**：所有狀態列舉在顯示層對照成中文（合成示範資料、已停用、尚未驗證），並配合狀態色。
- **驗收**：預設畫面不出現全大寫的內部代碼。

### P0-12 結果不要用 hash 當名字
- **問題**：回測結果下拉選單與比較頁的結果清單，顯示 64 字元 hash（例如 `800e4bdc63b586f79c9eae…`），使用者無法分辨哪一筆是哪一筆。
- **改法**：顯示可讀名稱「策略家族・主要參數・資料區間・建立時間（台北）」，hash 收進「進階」或 tooltip，內部識別仍用 hash。
- **驗收**：結果選單與比較清單不出現 hash；兩筆不同結果的顯示名稱不重複（必要時加序號）。

### P0-13 停用中的按鈕要說明原因
- **問題**：多個按鈕在預設狀態是灰色停用（例如「明確送出已預覽分析／比較」「以原始停止紀錄核對本機分析」「執行／讀取同一計畫」），但畫面沒說要先做什麼才能用。
- **改法**：停用按鈕的 tooltip 與旁邊的小字說明「需要先完成：○○」，前置條件完成後自動啟用。
- **驗收**：截圖工具列出所有停用按鈕，每一個都有原因說明。

### P0-14 完成通知不要重複
- **問題**：每完成一個背景作業，畫面同時出現狀態列「作業完成，結果已保存於本機。」和底部通知條「背景作業已結束。請核對來源、狀態與限制。」，而且通知條會一直留著，占用畫面。
- **改法**：合併成一則通知，數秒後自動淡出（錯誤除外，錯誤要手動關閉）；內容說明完成了什麼，並附「查看結果」連結。
- **驗收**：一次作業只產生一則通知；成功通知會自動消失。

### P0-15 根目錄的舊相依清單
- **問題**：根目錄 `requirements.txt` 是舊 AutoTradingPlatform 的相依清單（含 `shioaji==1.5.3`、`dash`、`cryptography==36.0.1` 等舊版），CI 刻意不稽核它（`.github/workflows/quantlab.yml:246`），但 README 舊段落仍寫 `pip install -r requirements.txt`（README.md:197）。新的開發者照著做，會裝到舊而且可能有漏洞的套件。
- **改法**：與 P2-B7 一起移到 `archives/legacy_autotrading/`；根目錄只留現行的 lock 檔，README 指向正確的安裝方式（P2-B8 的建置腳本）。若要先快速處理，可先在檔案開頭與 README 標示「舊程式專用，請勿安裝」。
- **驗收**：根目錄沒有會裝到舊券商套件的相依檔；README 不再指示安裝它。

### P0-16 應用程式圖示
- **問題**：`packaging/markauto.spec` 沒有設定 `icon`，程式也沒有呼叫 `setWindowIcon`，安裝後的捷徑、工作列與視窗都是預設圖示，看起來不像正式產品。
- **改法**：設計一個應用程式圖示（.ico 含 16–256 px），用於 exe、視窗、工作列、安裝程式與解除安裝項目。
- **驗收**：安裝後捷徑、工作列、「設定 → 應用程式」都顯示正確圖示。

> 以下 P0-17 ～ P0-20 為第三輪分析（實際操作紙上交易與 Walk-forward）新增。

### P0-17 每個作業的完成訊息都一樣
- **問題**：建立示範資料、回測、啟用策略、讀取帳戶、對帳、重播，完成後狀態列全部顯示同一句「作業完成，結果已保存於本機。」，使用者不知道實際發生什麼。例如重播 100 根後只產生 1 筆成交、帳戶現金從 1,000,000 變成 999,976，畫面上沒有任何摘要。
- **改法**：每種作業有自己的完成摘要，例如「回測完成：淨損益 -706 TWD、29 筆成交」「重播完成：處理 100 根、1 筆成交、目前空單 1 口」「對帳完成：帳戶 paper-demo 已可使用」。
- **驗收**：每個作業的完成訊息不同，且包含該作業的關鍵結果；有測試涵蓋每種作業。

### P0-18 「填入示範政策」按了沒有任何回饋
- **問題**：按「填入明示合成示範政策」後，表格確實填入了 4 個交易時段與 1 筆保證金，但狀態列完全沒有變化（實測維持原文字），表格又在頁面上方，使用者不知道有沒有成功。
- **改法**：顯示「已填入示範政策：4 個交易時段、1 筆保證金設定（合成資料）」並捲動到表格位置、短暫標示變更處。同類的表單填入動作一律比照。
- **驗收**：所有只改表單、不啟動背景作業的按鈕，按下後都有可見回饋。

### P0-19 重播結束後顯示「停止新委託：是」
- **問題**：重播一批歷史資料結束時，`PaperReplay.stop()` 會開啟停止開關（[quantlab/paper_replay.py:169-170](../../quantlab/paper_replay.py)），卡片因此顯示「停止新委託：是」。使用者看起來會以為觸發了緊急停止或發生錯誤。
- **改法**：行為不變（G2），但畫面區分「重播批次已結束（正常）」與「緊急停止（使用者觸發）」「風控觸發停止」三種原因，各自用不同文字與顏色。
- **驗收**：重播正常結束時，卡片不出現與緊急停止相同的字樣；三種停止原因有測試。

### P0-20 紙上交易頁的數字沒有反映帳戶
- **問題**：重播後帳戶已有 1 筆成交與 1 口空單，但頁面中間仍顯示「部位項目：0／委託項目：0／成交項目：0」。這組數字其實是「外部參考快照」表單的筆數，不是帳戶狀態，放在帳戶附近容易誤會。
- **改法**：帳戶狀態（現金、部位、委託、成交、是否需要對帳、是否停止）集中在一張帳戶卡片；參考快照的筆數改放在快照表單內，標示「參考快照」。
- **驗收**：重播或委託後，帳戶卡片的部位與成交數與帳本一致；畫面上不會有兩組意義不同的同名數字。

## P1 — 體驗重整（約 1–2 週，建議在 P2-A 之後）

### P1-01 AI 策略中心拆分
- **問題**：一頁混了策略參數、Walk-forward（18 欄）、研究生成器（16 欄），共 45 個輸入欄。
- **改法**：拆成三個分頁或子頁：「策略設定」「AI 研究」「Walk-forward 驗證」。每個子頁只放該工作需要的欄位。
- **驗收**：每個子頁預設高度 ≤ 1.5 個視窗（≤ 1,100 px）；所有原功能仍可操作，既有 E2E／整合測試通過。

### P1-02 Walk-forward 分步精靈
- **問題**：18 個欄位一次攤開，使用者不知道哪些必填、順序為何；「首折起點（自 0 起，含）」等用語難懂。
- **改法**：步驟化：①選候選池 ②選資料 ③設定窗口（提供「快速／標準／嚴格」預設組合，自訂才展開索引欄位）④預覽切分（用時間軸圖示呈現訓練／驗證／前推／保留集）⑤確認一次性消耗並執行。每步驗證通過才能下一步。
- **驗收**：預設組合下只需操作 ≤ 5 個控制項即可完成預覽；預覽、同意、一次性消耗、不重試 OOS 的規則完全不變（G2）。

### P1-03 新手引導與空狀態
- **問題**：使用順序「資料 → 策略 → 回測 → 比較 → 紙上交易」在畫面上沒有任何提示；空狀態只寫「尚無可用資料」，沒有下一步按鈕。
- **改法**：
  - 首次開啟顯示「開始使用」清單（可關閉、可從說明再叫出），每步顯示完成狀態並可直接跳轉。
  - 每個空狀態附一個主要動作，例如「建立範例資料」「前往匯入資料」。
  - 側邊欄依流程排序，未完成的前置步驟以提示標示，但不強制鎖住。
- **驗收**：全新工作區開啟時看得到引導；每個空狀態都有一個可點擊的下一步。

### P1-04 說明文字改為 tooltip 與「?」圖示
- **問題**：desktop UI 沒有任何 tooltip，所有解釋都寫成畫面上的長段文字。
- **改法**：欄位旁加「?」圖示，說明放 tooltip；頁面上只保留一行以內的必要說明。
- **驗收**：預設狀態下每頁標籤總字數相較第 2 節基準減少 ≥ 50%；原本的說明內容都能在 tooltip 或展開區找到。

### P1-05 去除工程用語
- **問題**：`fixture`、`OOS`、`bar 數`、`SHA-256`、`synthetic-assumption-v1`、`validated_dataset`、`TAIFEX:TMF:YYYYMM`、「排除最終保留集起點」等直接出現在一般畫面。
- **改法**：建立用語對照表（例如 bar → K 棒、OOS → 樣本外、fixture → 離線示範、validated_dataset → 已驗證資料）。技術代碼只在「進階」區顯示。下拉選單顯示中文名稱，內部值不變。
- **驗收**：截圖工具在預設狀態下，可見文字不含禁用詞清單（清單隨對照表一起提交）。

### P1-06 日期時間選擇器與台北時間
- **問題**：使用者手打 `YYYY-MM-DD` 與 `2026-01-05T01:00:00Z`，且全部要求 UTC。
- **改法**：日期用 `QDateEdit`（含日曆彈窗），時間用 `QDateTimeEdit`；畫面一律顯示並輸入 Asia/Taipei 時間，儲存與內部計算仍為 UTC，旁邊小字顯示對應的 UTC。
- **驗收**：所有日期／時間欄位改為選擇器；新增測試確認台北時間輸入轉成正確 UTC，且跨日（夜盤）不出錯。

### P1-07 結果以表格與卡片呈現
- **問題**：多處結果顯示在大型空白文字框，內容接近原始 JSON。
- **改法**：回測、比較、Walk-forward、紙上帳戶結果改成：關鍵指標卡片（淨損益、PF、描述性 Sharpe、最大回撤、已平倉 lot）＋明細表格（可排序、可複製）。「未定義」「未提供」照既有規則顯示（不得改成 0）。原始 JSON 收進「進階」。
- **驗收**：預設狀態下不出現大段 JSON；既有指標語意測試（PF／Sharpe 未定義原因）通過。

### P1-08 合約與到期日輸入簡化
- **問題**：使用者要手動填合約代碼與到期日表，資料匯入還必須另外提供交易日曆 JSON。
- **改法**：內建一份「有版本、有來源、已核對」的期交所合約到期日與交易日曆資料（隨版本發布更新，標示資料版本與核對日期）；使用者從下拉選單選合約，到期日自動帶入但可檢視來源。仍保留「不推算」原則：內建表沒涵蓋的日期照舊拒絕，並提示使用者手動提供。
- **驗收**：常見情境（近月 TMF）不需手填到期日與日曆；超出內建範圍時明確拒絕並說明。

### P1-09 設定頁精簡

### P1-11 視窗最小尺寸與響應式版面

#### P2-A4 拆分 execute_ui_operation
- **問題**：[desktop_ui.py:264](../../desktop_ui.py) 一個 329 行的函式處理所有背景操作。

### P2-B（其餘整理）

#### P2-B1 修正依賴方向
- **問題**：核心 [quantlab/desktop_runtime.py:817](../../quantlab/desktop_runtime.py) 在函式內 `from desktop_ui import execute_ui_operation`，核心反過來依賴介面層。
- **改法**：由 UI 層在啟動時把操作處理器註冊給 runtime（依賴注入），`quantlab/` 內不 import 任何 `desktop_*` 模組。在 `tools/quality_gate.py` 加上這條邊界檢查。
- **驗收**：`quantlab/` 下搜尋不到 `desktop_` 匯入；quality gate 新規則有測試。

#### P2-B2 解除循環匯入
- **問題**：以下模組互相匯入，目前靠函式內延遲匯入避開：
  - `desktop_runtime` ↔ `analysis_recovery`
  - `analysis_recovery` ↔ `research_analysis`
  - `research_analysis` ↔ `saved_candidate_pool` ↔ `walk_forward`
  - `desktop_ui` ↔ `desktop_walk_forward`
- **改法**：把共用的型別、常數、驗證函式抽到不互相依賴的底層模組。注意 `saved_candidate_pool.py` 雖不是 G3 鎖定檔，但它持有 profile 定義，改動要特別小心。
- **驗收**：GitNexus 或 import 分析顯示上述循環消失；函式內延遲匯入只保留有明確理由的（例如避免啟動時載入 Qt），並加註解。

#### P2-B3 縮短 desktop.main
- **問題**：[desktop.py:571](../../desktop.py) 的 `main` 有 348 行，混合參數解析、鎖、工作區準備、smoke test、電源事件與錯誤對話框。

- **驗收**：`main` ≤ 80 行；smoke test 與安裝器生命週期測試通過。

#### P2-B4 錯誤處理集中

- **改法**：新增共用錯誤模組（代碼列舉＋例外類別），與 P0-05 的使用者訊息對照表共用同一份代碼。G3 鎖定檔內的 `_fail` 不動，除非該檔因其他理由已需追加 profile。
- **驗收**：非鎖定檔改用共用模組；對照表涵蓋所有代碼（加測試防止遺漏）。
