## 3. 永久安全邊界（M2 版）

- **正式環境（`Environment.LIVE`）下單在程式層硬性關閉**：送單路徑只接受 `BROKER_SIMULATION` 與 `LOCAL`。
  以單一常數／函式集中判斷，並有測試證明 LIVE 下任何路徑（UI、策略週期、手動平倉、復原流程）都無法呼叫 `place_order`／`update_order`／`cancel_order`。
  LIVE 只允許登入、行情、帳務查詢。日後開放正式下單是擁有者另行決定的新工作，不在本規格範圍。
- 模擬環境使用 `Shioaji(simulation=True)`；**同一個 SDK session 不得在模擬與正式間切換**，切換環境須先 `logout`。
- 金鑰、CA 密碼只經 Windows 認證管理員與既有 `SecretResolver` 取得；不得顯示、記錄、寫檔或進入例外訊息。
- 未知值顯示「未知」；金額與價格用 `Decimal`；既有 fail-closed 檢查、OOS、預算、逾時規則不變。
- 不碰 G3 鎖定檔、`BROKER_SDK_VERSION`、`PROJECT_STATE.md`。

### M2-1 永豐連線整合（D2）

設定頁只保留一個「永豐連線」區塊，三步、逐級開放：

```
永豐連線   環境 [券商模擬 ▼]（正式：僅行情與帳務）
 ① API 金鑰引用  [MarkAuto/v2/broker/sinopac]   [儲存並連線]   ● 已連線
 ② 帳戶          ☑ 證券 9A95-xxxxxxx  ☑ 期貨 F002000-xxxxxxx   （登入後自動列出）
 ③ 交易憑證 CA   [選擇 .pfx 檔…]  密碼：以工具存入（見下）   ● 已啟用
 就緒狀態：行情 ✓   帳務 ✓   模擬下單 ✓   正式下單 停用
```

**必須**

1. 一次登入同時提供行情、帳務與（模擬）交易；取代 M1 的獨立行情 session 與舊 12 欄位表單，避免同一身分開兩條連線（每人上限 5 條）。
   M1 的行情功能（搜尋、K 線、回補、警示訊號）改由此連線提供，行為不變。
2. 「儲存並連線」一個按鈕完成儲存與連線；畫面帶入的預設值即可直接使用。
3. 帳戶：登入後以 `list_accounts` 列出，使用者勾選；帳戶代稱與帳戶對應由程式產生並保存，不再手填。
   顯示帳號時遮蔽中間位數。每個帳戶顯示 `signed`（API 約定書是否簽署）。
4. CA：只在「模擬下單」需要時才要求。檔案以檔案選擇器選取；CA 密碼以新工具（建議 `tools/store_sinopac_ca.py`，比照 `tools/store_sinopac_key.py`，
   存到 `MarkAuto/v2/certificate/sinopac`）存入，UI 只填引用名稱。`person_id` 從帳戶資訊取得，不讓使用者輸入。
   若永豐模擬環境下單實測不需要啟用 CA，則模擬下單不要求 CA，並在決策檔記錄實測結果。
5. 原本手填的商品規格、交易日曆、費用規則、帳戶資格證據、SDK 版本，改為程式自動取得或內建預設：
   商品規格由登入後合約資料取得；交易日曆、費用規則用內建版本（手續費折扣可在設定調整）；資格由 `signed` 與權限檢查得出；SDK 版本固定。
   既有需要 SHA 釘選的資源檔機制若仍被其他路徑使用則保留，但**新流程不得要求使用者準備檔案**。
6. 就緒檢查逐項顯示原因，例如「金鑰未勾選交易權限」「期貨帳戶未簽署 API 約定書」「模擬環境非服務時間」。
   權限不足以永豐實際回應判斷（不要猜測），對應到明確的中文訊息。
7. 舊設定（M1 的 `market_data_v1` 與舊連接器設定）自動轉換或忽略，不得讓已存在的工作區啟動失敗。

### M2-2 模擬環境下單開放（D1、D3）

1. `BROKER_SIMULATION` 允許 `execution_enabled=True`（`read_only=False`）；LIVE 依第 3 節硬性關閉。
2. 下單、改單、撤單沿用既有 `ShioajiGateway` 與 `TradingEngine` 流程；委託與成交以永豐主動回報（order/deal callback）接收，
   並定期 `update_status`／`list_trades` 對帳。程式紀錄與永豐不一致時自動「停止新倉」並列入待處理，不自動修正。
3. 首次在模擬環境啟用下單前，提供一個「模擬下單測試」按鈕：送出一筆最小數量、遠離市價、不會成交的 TMF 限價單後立即撤單，
   顯示結果（永豐開通正式環境前也要求這項測試）。只在 BROKER_SIMULATION 可按。
4. 永豐模擬環境有服務時段限制：非服務時段顯示原因並暫停自動交易，不重試轟炸。

### M2-3 跟著即時行情自動執行

1. 在 BROKER_SIMULATION 下，策略週期由即時 K 棒驅動：每個啟用策略在其週期 K 棒**完成**時評估一次（不使用形成中 K 棒），
   必要時下單。本機模擬保留既有「推進一個模擬交易日」。
2. 當沖強制平倉：到第 1 節時間點對所有當沖部位送出平倉；未成交時每 30 秒重送（最多到收盤前 2 分鐘），
   同時發出警示並停止所有新倉。收盤後仍有當沖部位時列為待處理異常。
3. 斷線或行情非即時：暫停新倉，保留保護性出場；恢復後先對帳再恢復。
4. 執行中的狀態（評估時間、下一次評估、最近一次下單結果）在總覽與交易頁可見。
5. 程式重啟或當機後，引擎維持既有「停止新倉」行為，**不自動恢復**；總覽、交易頁與頂部狀態列以醒目方式顯示
   「已暫停，等待恢復」與原因（例如「程式重新啟動」「對帳不一致」「單日虧損上限」），恢復須先對帳再由使用者按下。

### M2-4 多型態策略與策略管理（D4–D6）

1. 「新增策略」第一步選型態：當沖／短波／長波／自訂，自動帶入第 1 節預設值；之後選規則範本（沿用四種規則）或自訂 JSON、選商品、資金與單筆風險。
2. 商品限制依 D6：當沖預設只有 TMF；「現股當沖」核取方塊勾選時才可選股票，勾選時顯示「需具備現股當沖資格與額度」並要求確認。
   短波、長波只列股票（含 ETF），不列期貨。
3. 策略清單：名稱、型態、商品、環境、狀態（啟用／停用）、今日損益、最近訊號；可啟用／停用、複製成新版本、調參數（產生新版本）、刪除（已有成交紀錄者只能停用）。
4. 可同時啟用多個策略；各策略資金與風險獨立計算，總和不得超過帳戶配置。
5. 啟用前必須有通過的研究（回測）證據，沿用既有規則；當沖與分鐘週期策略使用 M2-7 的分鐘回測。
6. 部位大小（D9）：當沖 TMF 每次進場預設 1 口，可設 1–5 口；送單前以永豐回傳的保證金（模擬環境取不到時用內建保守值並標示）
   檢查可用資金，不足則不下單並記錄原因。股票以「每筆金額」換算整張（無條件捨去），不足一張不下單；不做零股。
7. 換月（D10）：當沖策略的商品設定為「微台近月」，由程式解析實際合約；結算日前一個交易日起解析為次月，結算日當天不開新倉。
   既有部位不跨日（當沖），因此不需轉倉。

### M2-5 風險控管

1. 帳戶層：單日虧損上限（預設配置資金 3%）、單筆委託金額上限、最大同時持倉數；觸發時停止新倉並警示。
2. 一鍵全停：停止所有新倉、撤銷所有未成交進場單，保護性出場保留（沿用「停止新倉並撤進場單」語意，放在頂部常駐可見處）。
3. 開盤前檢查清單（總覽頁）：連線、帳戶、權限、CA、行情是否即時、模擬服務時段、對帳結果；任一不通過則該日不自動開新倉。
   清單另提醒「盤中電腦需保持開機且不睡眠」（只提醒，不修改系統電源設定）。

### M2-8 測試不得殘留背景引擎（擁有者 2026-11-01 追加）

2026-11-01 安裝 0.3.0 時，安裝程式被 18 個測試或開發留下的 `desktop.py --trading-engine` 背景程序擋下（它們持有 MarkAuto 執行鎖）。
找出會啟動交易引擎子程序的測試與工具，確保在成功、失敗、逾時、例外各種情況下都會以正常關閉流程結束自己啟動的引擎；
新增一個測試證明測試結束後沒有殘留引擎程序。不得用強制結束其他非本測試啟動的程序來達成。

### M2-7 分鐘 K 回測（D11）

1. 研究（回測）支援 1m／5m 週期：資料來自 M1 的本機 K 線庫；持有以「分鐘」與「交易日」兩種單位計算，
   當沖在第 1 節強制平倉時間平倉，不跨日。
2. 成交模型沿用既有規則（訊號後下一根 K 棒開盤成交，不偷看未來），計入 TMF 手續費、期交稅與滑價（預設 1 跳，可調）。
3. 回測資料不足（K 線庫未涵蓋所需區間）時，先觸發 M1 的歷史回補，完成後再跑；不得以不完整資料產生證據。
4. 研究證據格式與既有日 K 證據相容，策略啟用的檢查邏輯不變；既有日 K 研究結果與指紋不得改變（以既有測試證明）。

### M2-9 股票資料、除權息、成本與到期提醒（擁有者 2026-11-01 追加，第二輪）

1. **股票多年日線**：短波、長波研究使用至少 5 年的股票日 K。新增證交所（上市）與櫃買中心（上櫃）個股日成交資料的下載與匯入，
   存入 K 線庫新增的日 K 表（`bars_1d`，來源標示 `OFFICIAL`）；已收盤交易日以官方日線為準，當日與分鐘週期仍用 M1 的 1 分 K。
   現有 `quantlab/market_providers.py` 只有加權指數與期交所資料，個股來源為新增；比照既有下載流程的同意、驗證與失敗保留原資料規則。
2. **除權息還原**：下載並保存除權息事件（上市、上櫃），研究與回測使用還原後的價格序列，避免除息跳空被誤判為下跌；
   圖表提供「原始／還原」切換；實際下單、部位大小與損益一律用原始價格。還原方式與事件來源寫入研究證據，使研究可重現。
3. **台股成本規則**：擴充 `quantlab/trading/domain/costs.py` 的 `FeeSchedule`：手續費 0.1425% × 使用者折扣（設定頁可填，預設 1）、
   最低手續費、賣出證交稅 0.3%、現股當沖證交稅 0.15%、ETF 證交稅 0.1%、TMF 每口手續費（設定頁可填）與期交稅十萬分之二。
   回測、模擬與風控共用同一份成本；修改成本產生新的成本版本（沿用既有 `cost_version`），既有研究證據不得被改寫。
4. **API 金鑰到期提醒**：永豐 API 若無法查詢金鑰到期日，在設定頁讓使用者填寫到期日；開盤前檢查清單與設定頁顯示剩餘天數，
   剩 14 天起提醒；登入因金鑰過期失敗時顯示明確原因。
5. **交易日曆年度提醒**：開盤前檢查清單確認交易日曆與期貨到期日涵蓋未來 30 個交易日；每年 12 月起提醒更新
   （沿用 `tools/update_taifex_expiries.py` 與既有日曆版本化格式），未涵蓋時不自動開新倉。
