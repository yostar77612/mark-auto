# M2-2b：人工模擬下單審查修正

Status: IMPLEMENTED（後端；UI 尚未接上新操作，見「待辦」）。實盤（LIVE）下單仍然硬性停用；
本次沒有新增任何會送單的路徑，下列新操作都**不會**呼叫 `place_order`。
對象：擁有者。程式碼、提交與 PR 以英文撰寫。

## 修了什麼

### F1 未知的送單結果可以恢復

以前：`place_order` 逾時但單其實已到券商時，之後每次對帳都會因為「找不到對應的本機單」而
`reconciliation_required`，帳本永遠停住，只能刪日誌。

現在：

1. **自動對回**：每筆人工模擬單都帶 `custom_field`（本機單號前 6 碼）。健康的對帳看到券商單的
   標記、代號、買賣、數量、價格都吻合**恰好一筆**未知單時，會自動綁回該筆，之後照一般事件流程處理。
2. **擁有者明確處理**（兩個新操作，都需要確認、都需要新鮮且健康的對帳、都不會送單）：
   - `ADOPT_MANUAL_ORDER`「採用這筆券商單」：對帳看到的券商單沒有標記但條件完全相同時，列為候選
     （`ManualPendingView.candidates`）；擁有者確認後綁定（可用 `target_id` 指定券商單號）。
   - `DECLARE_MANUAL_NOT_SENT`「宣告未送出」：對帳完全找不到對應券商單時，擁有者確認後把本機單
     標為已拒絕、釋放預留額度。**只要還有條件吻合的券商單，就拒絕宣告**（請改用採用）。
3. 處理完之後帳本仍是停止狀態，要用既有的「恢復」明確確認才能再下新單。
4. 與未知單無關的外部券商單仍然會讓帳本停住（`reconciliation_required`），行為不變。
5. 未知單未解決期間，持倉對帳暫緩（因為那筆單可能已成交）；解決後恢復比對。

### F2 改價結果未知不再卡死

- 對帳顯示價格仍是原價 → 這筆改價以 `manual_amend_not_applied` 關閉。
- 改價結果未知期間**可以撤單**（降低風險的動作，仍需確認）；仍不可再改價。
- 同樣的道理套用到撤單：撤單結果未知、對帳顯示委託仍在 → 以 `manual_cancel_not_applied` 關閉，可再撤一次。

### F4 送出前的 DomainError 不再當成「結果未知」

只有 SDK 真的被呼叫之後的例外才算未知。送出前的錯誤（例如 `state_conflict`、
`capability_missing`）：原樣回報、本機單標為已拒絕並釋放預留、撤單失敗則還原委託狀態，
且**不會**停住引擎。SDK 呼叫之後的逾時／例外行為不變（停住、保留預留、不重送）。

### F3 限價偏離保護（預設 1%）

會立即成交方向的限價（買價高於賣一、賣價低於買一）超過 `MANUAL_MAX_PRICE_DEVIATION`
（`manual_book.py`，預設 1%）時，預覽不通過（`price_deviation`），確認時以最新行情再檢查一次。
遠離行情的掛單不受影響（微台測試單正是如此）。預覽資料附上目前買賣價（`ManualPreviewView.bid/ask`）。

### F5 平倉單可改價

平倉單不預留現金也沒有停損，改價不再套用「停損 < 價 ≤ 限價」的限制（舊規則對平倉單永遠不可能通過）；
價格仍須符合跳動單位與當日漲跌停。

## 新增測試

`tests/test_manual_review_fixes.py`（F1–F5 行為）與 `tests/test_manual_review_guards.py`（防護測試）。
每個防護都做過突變驗證：把防護刪掉或反轉後，至少一個測試會失敗（結果見 PR 說明）。
