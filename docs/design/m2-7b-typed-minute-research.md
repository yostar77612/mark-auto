# M2-7b：參數化策略的當沖分鐘研究

## 目標

畫面上建立的「參數化策略」選「當沖」後，能用微台（TMF）的 1 分／5 分 K 線做研究，
結果可在畫面上看到；之後才談模擬執行。本文件記錄範圍、決定與分階段做法。

## 現況（2026-11-09 盤點）

- 分鐘研究函式 `research_minutes` 與 K 線補抓、完整場次檢查、receipt 都已存在，
  但只接受舊式（非參數化）策略；參數化策略一律以 `capability_missing` 拒絕。
- 引擎的研究步驟只走日線研究；沒有任何程式把參數化當沖策略送進分鐘研究。
- 分鐘 receipt 刻意不能授權日線引擎（不同的指紋命名空間），這點不變。
- 本機模擬（LOCAL）沒有分鐘資料，無法驗證當沖；需要永豐連線與 K 線，登入由你操作。

## 本次決定

1. 只限微台。股票當沖不做分鐘研究（資格與額度仍由帳戶決定）。
2. 參數化策略的 `bar_interval` 必須與研究設定的區間一致，否則 `validation_failed`。
3. 口數取策略凍結的 `contracts`；成本與損益按該口數計算。未參數化的舊式訓練維持 1 口。
4. 指紋把參數納入（既有 `research_fingerprint` 已處理），分鐘命名空間不變，
   所以結果不能授權日線引擎、也不會與舊結果混淆。
5. 研究不模擬保護性停損（日線研究也不模擬）；文件與結果明確標示，避免被當成含停損的績效。

## 分階段

| 階段 | 內容 | 狀態 |
| --- | --- | --- |
| A | 研究函式接受參數化策略（本 PR），離線假資料測試 | 完成 |
| B | 引擎研究步驟：當沖參數化策略 → 分鐘研究主機 → 儲存分鐘 receipt；畫面顯示結果與缺連線時的具體指引 | 未做 |
| C | 模擬執行：以即時分鐘 K、收盤前強制退出與保護性停損執行當沖單 | 未做，需另行設計 |
| D | 以你的永豐 K 線資料做真實驗證 | 需要你登入連線 |

階段 B、C 動到交易核心，不在階段 A 啟用；未完成前畫面上的當沖研究行為不變。

## 階段 B 前置盤點（2026-11-09）

- 分鐘研究主機 `run_minute_research` 已完整：永豐 K 線補抓、完整場次檢查、獨立行程計算、
  收據寫入 `research/minute-receipts.sqlite3`；整條路徑目前沒有任何呼叫端（只有測試）。
- 可選接法：(1) 在 `workflows.run_research` 對參數化微台當沖分支，經 runtime 注入的可呼叫物件進主機，
  結果存進策略記錄；(2) 新增獨立 UI 動作與 IPC 操作，結果只存在分鐘收據庫，不碰策略記錄。
- 風險（必須先解）：接法 (1) 會讓策略進入 `RESEARCHED`，`engine.deploy` 的證據檢查與
  `_assert_strategy_evidence` 是為日線結果設計的；未完成階段 C（當沖執行）就開放「啟用」，
  會把引擎無法正確執行的當沖策略放上線。因此階段 B 必須同時：
  明確拒絕分鐘結果的啟用（具體錯誤文字）、畫面標示「僅研究」、並以測試證明不能啟用。
- 接法 (2) 不碰策略記錄，風險較低，但要新增 UiAction／IPC operation／server 路由／UI 顯示，
  並更新對應基準；結果只能以收據顯示。
- 這兩者都無法在本機驗證真實資料（需要永豐連線與 K 線），所以階段 B 完成後仍須由你連線做階段 D。
- 建議：先做接法 (2) 的最小版（只讀、僅研究），階段 C 另做完整設計後再開放啟用。
