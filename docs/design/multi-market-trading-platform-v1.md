版本 v1.0　日期 2026年10月25日　適用對象 產品使用者與後續開發維護者

狀態 PROPOSED / NOT IMPLEMENTED。本文定義目標功能、分層、介面契約、實作順序及驗收條件；建立文件不代表任何券商連線或交易功能已完成。既有正式驗收分數與實盤停用狀態維持原狀。

本次決策是以同一套平台支援台股現股、台指期與個股期貨，將商品類型、持有週期、執行環境與帳戶權限分開管理。第一個使用情境是證券現股做多、持有三至五個交易日或約一週；取得資格後增加當沖，再接入期貨。長期持有及夜盤的資料與介面邊界第一輪就納入，依各項驗收逐步開放。

## 1 已確認需求與產品邊界

### 1.1 使用者已確認的設定

| 項目 | 已確認內容 | 系統處理方式 |
|---|---|---|
| 首批帳戶 | 先申請永豐證券戶，之後申請期貨戶 | 帳戶及權限獨立開通，不要求同時具備 |
| 起始資金 | 約新臺幣100,000元 | 平台共用總預算，證券與期貨分帳配置 |
| 單筆風險 | 總資金約2%至3% | 約2,000至3,000元，含預估往返成本及滑價 |
| 單日虧損 | 總資金約10% | 約10,000元，跨策略與帳戶合計 |
| 初期時段 | 日盤 | 夜盤先保留模型及設定，預設關閉 |
| 資格未齊時 | 現股短期持有 | 預設三至五個交易日，約一週可選五個交易日 |
| 長期方向 | 策略可切換長期、短期或當沖 | 建立新策略版本，不直接改寫已持有部位的規則 |
| 操作風格 | 簡潔、容易理解 | 常用決策置前，技術細節放進階區及診斷頁 |

百分比先解讀為平台配置資金的比例，不是股價漲跌百分比，也不是投入每筆交易的資金比例。2%至3%仍是範圍；設定畫面必須讓使用者選定單一執行值，啟動摘要不得顯示模糊範圍。規格範例用2%，不代表已替使用者決定正式參數。

10%日虧上限是使用者提出的規畫值，屬較寬的風險額度；正式啟用前應以模擬和小額驗證評估較低限額。任何損失門檻都是控制目標，跳空、流動性不足與無法成交可能使實際損失超過門檻。

### 1.2 第一輪納入與後續擴充

第一輪納入三類商品的資料模型、策略持有政策、研究流程、資金風控、委託生命週期、對帳復原、介面及測試替身。股票先涵蓋普通現股及整股交易；短期和長期投資可在獨立驗收後增加零股路徑，現股當沖不可藉零股路徑替代。[S1][S2]

融資、融券、借券、選擇權、跨券商套利和高頻低延遲交易保留擴充位置，第一版不宣稱可用。台股先賣後買、期貨當沖減收保證金、夜盤都屬獨立能力，不能因為 API 登入成功就一起啟用。

「權限開通即可接上」的工程目標，是補入帳戶設定、完成連接器聯調與指定測試後，沿用原有畫面和交易流程。無法預先保證券商未來介面零變更，因此必須鎖定 SDK 版本，讓版本差異集中在永豐連接器。

## 3 三類商品與四種持有政策

### 3.1 商品與週期能力矩陣

| 商品 | 當沖 | 三至五日與一週 | 長期持有 |
|---|---|---|---|
| 台股現股 | 資格、標的及方向確認後啟用 | 首批重點，現股做多並預留足額交割款 | 納入股利、公司行動及持續資金占用 |
| 台指期 | 實際月份、時段及保證金驗證後啟用 | 另驗證跨日結算及隔夜風險 | 必須有到期處理及明確轉倉政策 |
| 個股期貨 | 納入價差、深度及可交易狀態 | 另驗證公司行動與調整契約 | 必須處理契約到期、乘數變更及轉倉 |

各格都是獨立可驗收能力。股票的「多空方向」與策略的「長短持有時間」使用不同欄位；「長期」不能被誤解成只能做多。

### 3.2 持有政策的精確語意

HoldingPolicy 分為 INTRADAY、SWING、POSITION、CUSTOM。日盤或夜盤由 SessionPolicy 控制；日內平倉與減收保證金由不同欄位控制。

| 政策 | 主要設定 | 出場語意 |
|---|---|---|
| 當沖 | 指定盤別、停止進場及平倉時間 | 在指定時段結束前執行退出並確認殘餘部位 |
| 短期 | 正常持有3至5個交易日 | 預設最晚第5個交易日退出；保護性退出優先 |
| 約一週 | 目標5個交易日 | 使用交易日曆計算，不直接加7個日曆日 |
| 長期 | 自訂最長交易日數、檢視頻率 | 依趨勢、風控或期限退出；股利與到期規則持續有效 |

持有日數以首次進場成交所屬交易日為第0日；第3日指該商品交易日曆往後第3個交易日。每日截止點以商品時段和排程政策決定；部分成交加碼不重設整筆部位的最長期限，除非事先選擇逐批部位政策並通過驗收。

正常最短持有日數只限制一般策略退出，不能阻止合法可執行的停損、風險減碼或異常處理。停牌、休市、缺漏日曆及期貨到期都不能用合成可交易日補齊。

### 3.3 尚未取得當沖資格的行為

預設為現股做多、跨日持有、足額預留交割資金，停用現股先賣後買與日內往返策略。永豐目前公布的現股當沖條件包含開戶滿三個月、近一年成交達十筆及相關簽署；是否具備資格以永豐確認結果為準。[S1]

資格未齊時，當日新買部位不能被假設隨時可日內賣出。EligibilityService 必須核對券商可賣數量、部位來源、帳戶及交易類別；可賣資訊無法確認時停止增加曝險。使用者須在進場前看見可能跨日承擔風險的提示；若要求保證當日可退出但權限不足，該筆進場直接拒絕。

保護性退出一律先檢查合法交易能力；不得用錯誤交易類別、假借既有庫存或繞過資格來送單。無法透過 API 執行的退出須保留未處理狀態並提示人工聯絡券商。每日平倉規則只套用當沖部位，跨日策略不因收盤被全部賣出。

### 3.4 隨時切換策略的行為

使用者可隨時提出週期或規則變更。每次變更產生新的 StrategyVersion，重新完成資料適配、回測與啟用檢查，再套用到新進場。已持有部位繼續綁定進場時的策略及退出政策。

若要把既有部位轉交新策略，介面必須預覽期限、停損、資金與帳戶差異；在對帳一致且無衝突委託後，記錄明確的部位移交事件。不能把當沖未平倉單自動改標成長期持有來掩蓋異常。

## 4 介面結構與主要操作

### 4.1 六個主要工作區

| 導覽名稱 | 使用者主要問題 | 預設內容 |
|---|---|---|
| 總覽 | 今天系統在做什麼 | 資金、風險剩餘、策略狀態、待處理事項 |
| 策略 | 我想怎麼交易 | 市場、持有週期、方向、AI草案、驗證及版本 |
| 市場 | 可以交易哪些商品 | 候選商品、圖表、行情新鮮度、可交易原因 |
| 交易 | 我的單與部位怎麼了 | 委託、成交、持倉、退出期限及操作 |
| 績效 | 策略是否符合預期 | 淨損益、回撤、成本、持有天數及版本比較 |
| 設定 | 帳戶與限制是否就緒 | 永豐連線、資格、資金、風控、引擎及維護 |

沿用現有資料匯入、回測、比較、研究及復原功能，整合到上述工作區的次層入口。保持資料來源、環境、權限及待對帳提示在可見範圍。進階參數、SDK版本、事件序號和診斷資訊預設收合。

### 4.2 策略設定的操作順序

使用者依序選擇市場、持有時間、方向、商品範圍、資金與風險；再選 AI 協助產生規則或既有策略。一般畫面使用「持有3至5個交易日」「當日收盤前退出」「單筆預估風險2,000元」等用語，詳細計算在旁可展開。

AI草案頁同時呈現進場、退出、預估交易頻率、成本假設及適用條件，並附可解釋的範例。回測結果完成後再進入模擬與啟用摘要。啟動一次明確綁定策略版本、帳戶、商品範圍及風險限額，在此範圍內由引擎依規則執行，無須逐筆彈窗。

啟用頁列出尚未符合的條件與具體處理方式。例如「尚未確認現股當沖資格，可先選跨日持有」；不能在背景自動將策略改成不同週期。

### 4.3 總覽與交易畫面的資訊層級

```text
頂部  觀察或模擬或正式  帳戶  引擎狀態  行情時間
摘要  配置資金  今日淨損益  剩餘風險  待處理異常
主區  啟用策略及持有政策  持倉及預計退出日
操作  停止新倉  查看委託  處理待對帳事項
底部  最近事件與可展開的完整紀錄
```

持倉列表必須包含商品、來源策略、數量單位、可賣或可平數量、持有交易日數、目標退出日、保護狀態與最新行情時間。當沖和跨日部位同時存在時，使用文字標籤區分，不依賴顏色。

### 4.4 操作按鈕與失敗狀態

| 操作 | 明確效果 |
|---|---|
| 停止新倉 | 停止增加曝險並撤銷進場委託；保護性退出繼續 |
| 撤銷進場單 | 只撤增加曝險的未成交委託，不批次刪除保護單 |
| 平倉所選部位 | 預覽商品、數量、帳戶與範圍，再執行可合法退出的數量 |
| 關閉介面 | 顯示背景引擎是否繼續；不能讓使用者誤認全部停止 |
| 關閉引擎 | 有持倉時列出本機保護將受影響的範圍及未完成事項 |
| 恢復新倉 | 對帳完成且風控允許後，以明確動作解除可解除的暫停 |

所有畫面涵蓋載入、無資料、權限不足、行情過期、連線失敗及需對帳。錯誤訊息說明發生什麼、影響什麼、接著能做什麼，技術錯誤碼放診斷區。保留鍵盤操作、焦點順序、中文名稱和可讀字級。

## 5 分層架構與共用程式邊界

### 5.1 依賴方向

採用同一程式庫內的模組化架構，交易引擎使用獨立程序。初期不增加分散式微服務、訊息平台或多套資料庫。組裝入口負責建立服務與注入連接器，其他模組不能自行建立券商單例。

```text
桌面畫面及展示模型
        ↓
應用服務與使用案例
        ↓
領域模型及交易規則 ← 埠介面
                         ↑
        永豐連接器  模擬器  儲存及系統介面

組裝入口選擇環境並注入依賴
引擎與桌面透過版本化本機命令及事件通訊
```

| 層次 | 責任 | 邊界 |
|---|---|---|
| Presentation | 表單、圖表、展示模型、導航 | 不計算風控，不持有金鑰，不直接呼叫SDK |
| Application | 策略啟用、資料作業、執行協調、對帳 | 呼叫領域及埠，不包含券商欄位細節 |
| Domain | 商品、部位、目標、持有政策、費用、風控 | 純資料及確定性邏輯，不依賴Qt、SDK或資料庫 |
| Ports | 行情、帳戶、委託、日誌、日曆及時鐘契約 | 使用自有DTO及型別，不暴露SDK物件 |
| Adapters | Shioaji、模擬、SQLite、檔案、系統時間 | 轉換資料與例外，執行能力檢查 |
| Runtime | 程序生命週期、命令接收、單寫入者、組裝 | 控制啟停、健康及環境，不藏交易規則 |

### 5.2 共用與專屬模組

共用的內容包括 Decimal 金額、數量單位、時間與交易日、策略版本、目標部位規畫、資金預留、委託狀態、事件去重、對帳、持有期限、風險入口和畫面狀態。商品差異集中到 StockRules、IndexFutureRules、StockFutureRules，以及版本化的規則資料。

股票的交割與可賣量、期貨的保證金與結算、個股期貨的調整契約分別實作，透過共同介面提供結果。不能把不同交易制度硬塞進一個大型函式，再用大量商品類型判斷分支。

同一項費用、時間或數量算法只保留一個權威實作，回測、模擬及交易服務共用。撮合模型、資訊可得性和實際執行差異必須保持明確，不能因共用介面就宣稱三種環境成交完全一致。

### 5.3 預定目錄與遷移方式

下列均為未來新增路徑，並非已存在模組。可在實作時依既有命名收斂，但責任邊界必須保留。

```text
quantlab/trading/
  domain/       instruments policies strategy orders positions risk
  application/  research deployment execution reconciliation
  ports/        market_data account execution storage calendar clock
  adapters/
    shioaji/    connection market_data account execution mapping
    simulated/  feed matching account failures
    storage/    journal repositories migrations
  runtime/      engine commands events lifecycle
desktop_pages/  沿用既有頁面入口並逐頁導入窄服務
desktop_trading/ presenters widgets forms
tests/trading/  domain contracts adapters recovery scenarios
```

先新增v2型別、適配及特徵測試，再逐個使用案例遷移。禁止一次搬移所有舊模組或改寫歷史結果。既有 PaperBroker 的合成事件不能假裝成券商實際回報；兩者可共用事件格式，但必須保留來源及驗證狀態。

## 6 商品與資料管理

### 6.1 商品主檔

InstrumentSpec 至少包含 schema_version、instrument_id、asset_class、exchange、currency、underlying_id、delivery_month、expiry、quantity_unit、order_unit、unit_size、multiplier、tick_rule_id、session_calendar_id、settlement_rule_id、corporate_action_version、effective_from 及來源版本。

股票內部數量以股記錄；期貨內部數量以口記錄。顯示張數與 Shioaji 委託數量在適配邊界精確轉換，必須同時攜帶單位。一般整股路徑不接受不能整除交易單位的數量，零股使用獨立能力與撮合設定。

期貨執行身分必須對應實際到期月份及當時規格；研究用近月或連續序列先經 ContractResolver 解析成實際契約。未知、調整中或規格已失效時停止新倉，不以根代碼猜測。個股期貨可以由標的反查，仍須區分標準、小型與調整契約。[S3]

### 6.2 行情與日曆

QuoteEvent 保留來源市場時間、接收時間、交易日、盤別、成交或報價類型、序號可用性、資料來源與品質旗標。沒有官方事件序號時，連接器需說明去重限制，不能自行宣稱資料完整。

歷史資料與即時資料經同一正規化入口，另保留調整前價格與研究用還原價格的區分。K線只在完成且已可得時參與決策；回測不能用收盤價計算訊號後，再假設同一根開盤成交。日線策略不能利用尚未完成當日K線的最終數值。

日曆使用官方或經核對的版本化交易日與時段，支援臨時休市、停牌、延後收盤、到期日及夜盤交易日歸屬。日曆缺漏時拒絕受影響的新進場與期限計算，保留人工處理資訊。

### 6.3 資料、選股與公司行動

資料下載分頁、快取、配額及重試集中處理。空回應與資料不足不能解讀成零成交；查核配額、商品、日期與連線狀態。歷史資料可得期間及細度以當時API和資料來源能力確認。[S4]

選股以當時可得的商品名單、資格、量能、價差與深度建立候選快照；回測不得使用今天的成分名單回推歷史。訂閱容量優先保障持倉和待成交單，再分配候選商品；流量不足時縮減候選並停止受影響的新倉。

跨日股票處理股利、分割、合併、減資及其他公司行動；個股期貨處理契約調整與乘數生效。事件無法正確套用時凍結受影響商品，保留原始資料和對帳差異，不自動覆寫部位。

## 7 AI策略與研究生命週期

### 7.1 策略定義

StrategyDefinition 至少有策略ID及版本、資產類別、候選範圍、資料頻率、持有政策、允許方向、進出場條件、部位算法、成本版本及風控引用。AI輸出只允許受限的結構化規則，經 schema、運算子白名單、型別、資源上限及資料可得性驗證。

```json
{
  "schema_version": 2,
  "strategy_id": "swing_stock_example",
  "version": 1,
  "asset_class": "STOCK",
  "direction": "LONG_ONLY",
  "bar_interval": "1d",
  "holding_policy": {
    "kind": "SWING",
    "unit": "TRADING_DAY",
    "normal_exit_min": 3,
    "max_holding_days": 5,
    "entry_day_index": 0
  },
  "entry_rule_ref": "validated_rule_set",
  "exit_rule_ref": "validated_exit_set",
  "risk_policy_ref": "user_selected_policy"
}
```

這是契約形狀示例，引用的規則仍須存在且通過檢查；不是可直接下單的策略。止損和風險控制不由AI文字中的承諾替代。

### 7.2 版本與驗證流程

狀態依序為草案、規則有效、回測完成、前進驗證完成、即時紙上觀察、券商模擬驗證、可啟用及退役。券商模擬未支援的情境須另外測試並標示，不得因缺少功能而跳過驗收。各市場與持有週期的資格分別記錄。

修改週期、進出場規則、商品類別、資料頻率或成本假設，產生新版本並失效相關驗證。不能僅改「持有天數」就沿用原當沖績效。績效比較包含淨損益、回撤、曝險、周轉率、成本、流動性、隔夜跳空及持有天數分布。

研究資料分為訓練、樣本外及最終保留集；既有一次性消耗、失敗不退還預算及資料隔離保持有效。樣本外和最終保留資料不可傳入AI對話或工具輸出。AI可產生或解釋草案，不能取用券商密鑰、直接送單、提升權限或修改已啟用風控。

### 7.3 多策略共存與AI故障

引擎在同一決策快照上收集目標，依帳戶與商品規畫淨委託；策略子帳保留部位歸屬。相互衝突、額度不足或同一標的方向不明時，以事先設定的優先序及上限處理，結果必須可重播。

同帳戶同商品若無法可靠分配實際成交及券商沖銷，第一版限制為單一啟用策略，介面說明原因。不能以總淨部位相同就宣稱各策略持有期限和成本正確。

AI服務離線、逾時或額度不足時，既有已驗證策略及保護性退出不依賴即時AI回覆；需要新草案或新判斷的進場暫停。策略規則不得在執行期間被模型自行熱更新。

相同冪等鍵及相同內容回傳原命令結果；相同鍵不同內容拒絕。這項保證只涵蓋本機命令，券商不一定提供相同的冪等機制。券商送出結果未知時進入UNKNOWN並對帳，不能以本機鍵保證遠端絕不重複。

錯誤碼至少區分 capability_missing、eligibility_unknown、insufficient_funds、risk_rejected、stale_quote、state_conflict、rate_limited、broker_rejected、outcome_unknown 和 reconciliation_required。依專案既有 ERROR_TABLE 增補，使用者訊息與SDK原始錯誤分離。

股票的現股交易條件及先賣後買旗標，與期貨的新倉、平倉、當沖倉別分開映射。持有政策 INTRADAY 不直接等同期貨 DayTrade 倉別；減收保證金另需符合當時商品、月份、時段及帳戶條件。[S5][S6][S10]

模擬環境需要API金鑰，也有功能範圍限制；本機替身必須涵蓋模擬環境無法重現的異常。正式啟用前確認對應證券或期貨簽署、測試、金鑰權限及CA憑證。[S7][S8][S9]

## 9 委託與部位生命週期

### 9.1 狀態轉移

```text
CREATED → VALIDATED → RESERVED → SUBMITTING
SUBMITTING → ACCEPTED → PARTIALLY_FILLED → FILLED
SUBMITTING → REJECTED
SUBMITTING → UNKNOWN → 查詢及對帳後確認
ACCEPTED或PARTIALLY_FILLED → CANCEL_PENDING
CANCEL_PENDING → CANCELED 或後續成交狀態
```

委託狀態與已成交數量分別儲存；已部分成交再撤單仍保留成交部位。取消成功只表示剩餘委託取消，不能把已成交數量歸零。改價或減量要保留命令鏈及資金預留調整，增加數量若不支援則走明確的新委託流程。

### 9.2 一致性與外部操作

帳戶的資金及委託操作由單寫入者序列化；先寫入意圖、預留與待送事件，再送券商。回報去重、原始資料引用及正規化事件持久保存，儲存失敗時停止新倉。事件重放必須重建相同部位、預留與損益。

斷線、回報亂序、重複或缺漏時，停止受影響的新倉並補查。無法唯一對應券商單的未知結果維持隔離，不能自動補送。恢復連線不等於恢復交易，必須完成委託、成交、部位及資金對帳。

手機下單、人工撤單、帳戶入出金及券商強制處理視為外部事件。系統管理部位與外部部位明確分離；「全部平倉」預設只涵蓋已接管部位，擴大至帳戶全部部位須在當次操作中清楚呈現。

### 9.3 出場協調

停損、停利、持有期限與風控平倉共用 ExitCoordinator，以部位及未成交退出單計算剩餘可平量。多個退出觸發只能形成一個一致計畫，避免重複賣出或反向開倉。

交易系統若不提供可驗證的原生互斥或只減倉功能，連接器不得假裝存在。保護單由券商端或本機執行的方式、適用時段與斷線行為須標示；本機觸價需要引擎及行情持續運作。

## 10 資金與風控規格

### 10.1 計算基準

每個交易日以配置資金及核對後淨值建立日初基準，記錄交易日、估值時間及資金異動。現金入出金調整基準但不算策略損益；日內獲利不自動放大單筆上限。跨日持倉每日重新估值，未知估值不得被當成零風險。

單筆預估風險由停損距離、每單位價值、數量、往返費稅及滑價緩衝組成。停損位置由策略有效條件決定，再依風險預算計算數量，不能為買到更多數量任意縮短停損。[S11]

```text
單位風險 = 停損價差 × 每單位價值 + 單位往返成本及滑價
風險允許數量 = 單筆可用風險 ÷ 單位風險後向下取整
最終數量 = 風險、資金、額度、流動性與部位限制的最小值
```

計算後還需按張股或口數規則取整；數量為零即拒絕，不擴張風險預算。未知費用或保證金必須使用有依據的保守設定並標示，無可用設定時拒絕新倉。

### 10.2 風險預算與日虧

| 限制層次 | 內容 |
|---|---|
| 單筆 | 使用者選定2%或3%等單一值，成本與滑價一併納入 |
| 商品與標的群 | 個別商品、相同股票及其期貨的合計曝險 |
| 策略 | 資金配置、同時持倉、每日虧損及頻率 |
| 帳戶 | 證券額度與交割、期貨保證金及緩衝 |
| 平台 | 共用100,000元配置及10,000元日虧規畫上限 |
| 作業 | 連續虧損、回報異常、拒單率、資料品質及風控服務健康 |

日虧以費稅後已實現損益及未實現損益合計計算；估值不新鮮時停止新倉。既有保護單、待成交進場單及UNKNOWN單都需預留風險和資金。新增單預估不利損失加既有剩餘風險，不得超過當日剩餘額度；獲利不重設已鎖定的日停狀態。

股票和個股期貨的同標的風險不能各自拿滿限額；台指曝險另設整體名目及情境上限。未建立可靠相關模型前，使用明確分組和保守上限，不以估計相關係數宣稱可互相抵銷。

### 10.3 證券資金與期貨保證金

現股跨日買進採足額自有資金政策，依交割日預留買款及費用。券商交易額度、帳戶淨值、已交割現金及未交割應收款分開記錄；不能把尚未收取的賣款一律當成可立即使用現金。普通交易交割及例外規則依當時市場與券商資料核對。[S2][S12]

期貨採有生效日期的保證金與結算規則，留足價格變動及費用緩衝。100,000元是總預算，不代表任一合約都可交易；TX、MTX、TMF及各個股期貨分別計算。是否適用當沖減收保證金獨立查核，不預設所有日內交易減半。[S10]

### 10.4 觸發與鎖定

達日虧門檻後，鎖定新倉、撤銷增加曝險的委託並執行事先選定的風險減碼政策。保護性退出走合法可執行路徑，不能因新倉鎖定被一起停用。日停鎖跨重啟保存，當日不得由AI、重啟或簡單改設定繞過。

跨日持有的隔夜風險、週末及連假曝險需獨立上限；停損價不能保證跳空時的實際成交價。長假前是否停止進場或降低持倉必須有策略政策及回測假設，不能在執行時臨時猜測。

## 11 排程與持有期限處理

當沖部署有盤前檢查、可進場、停止進場、撤銷進場單、退出、殘餘處理及盤後對帳等階段。截止時間使用相對商品時段的政策，並處理到期日及特殊時段；不把股票收盤時間硬套所有期貨。

短期與長期部署盤前檢查可交易性、公司行動、交割或保證金和持有天數；盤中保護性退出持續有效，盤後保存跨日快照及次日待辦。到期策略部位按照已選定的可交易時點退出，不因到達目標天數就虛構成交。

日盤執行與允許隔夜持有是兩個選項。日盤跨日部位可能在非運行時段承擔價格變動，介面須顯示保護可運作時段；夜盤尚未開放時，不宣稱夜間有自動保護。期貨跨到期的長期策略必須明確選擇到期前退出或轉倉，轉倉以兩筆真實成交及成本記錄，不把換月視為免費改代碼。

## 12 引擎復原與安全管理

### 12.1 程序與通訊

桌面與引擎分離，使用本機命名管道或等價受保護IPC，限制同一使用者、訊息大小、命令有效期及可執行命令。初期不向網路開放交易服務。所有入口最後進入同一應用服務與風控路徑。

每個帳戶及環境只允許一個有效執行者。鎖、租約及失效復原需避免舊執行者恢復後繼續送單；驗證失去所有權的程序無法送出。研究作業與交易程序分開資源及排程，長時間回測不得阻塞保護性退出。

### 12.2 啟動與故障

重啟順序為取得所有權、讀取日誌、核對版本、連線、補查券商、重建預留、確認部位及保護狀態，再進入待恢復。預設不因電腦開機自動恢復新倉；可持續執行已授權且已確認的保護流程，任何無法確認範圍維持待處理。

引擎或磁碟故障、系統時間偏移、憑證失效、帳戶資格改變、網路中斷及行情訂閱不足都有明確事件與處理。重試只適用可安全重試的查詢；交易結果未知先對帳。關閉、升級或還原版本前，須保留券商未結委託和持倉的處理責任。

### 12.3 金鑰與資料

API密鑰及憑證密碼使用Windows Credential Manager或等價作業系統保護，憑證檔放在程式庫及一般工作區備份之外。設定只保存引用、遮蔽帳號及必要狀態；日誌、報告、崩潰資料和AI內容不得包含密鑰、完整身分證號或憑證內容。[S7]

本機模擬、券商模擬、正式環境使用不同資料目錄、資料庫及帳戶身分。帳戶能力過期或未知時預設拒絕新倉。SDK更新先在隔離環境完成回歸；不能自動升版後在持倉期間無提示切換交易行為。

## 13 儲存與可觀測性

交易資料使用單一本機SQLite交易儲存，加大型行情檔案快照；保留現有已修補SQLite版本及檔案系統要求。研究、展示快取與交易帳本分區，UI讀模型不可反向修改交易狀態。

主要紀錄包括商品規格版本、交易日曆、策略版本、部署、使用者設定、日初基準、資金配置、預留、意圖、委託命令、券商事件、成交、部位批次、公司行動、對帳差異及引擎控制。事件保存原始引用與正規化版本，衍生快照可重建。

每個事件串起 deployment_id、strategy_version、decision_id、plan_id、command_id、local_order_id及broker_order_ref。日誌記錄原因及結果，敏感資料遮蔽。觀測指標包含行情年齡、命令及回報延遲、拒單、未知單、對帳差異、日誌寫入狀態和引擎心跳。

日報按策略、市場及持有週期拆分已實現與未實現損益、費稅、滑價、回撤、未平部位及未解異常。正式成交與紙上成交不能混合產生一條未標示的績效線。

備份需包含一致性快照、schema版本及來源事件位置；復原到舊備份後先全帳戶對帳，不可直接送出舊待送佇列。保留政策、磁碟上限及清理規則可設定，未解委託、成交與稽核資料不得被一般快取清理刪除。

## 14 程式碼維護性與品質門檻

### 14.1 共用抽取原則

共用模組須有至少兩個明確使用情境或穩定的領域責任；避免建立雜項utils或萬用Base類別。透過小型Protocol及不可變DTO定義邊界，組合優先於深層繼承。不同市場只實作差異規則，共同風控及委託協調各保留一個入口。

禁止UI匯入SDK或資料庫、領域匯入畫面、連接器呼叫畫面，以及Application直接依賴Shioaji型別。以自動依賴檢查驗證，不能只靠目錄名稱宣稱分層完成。必要組裝例外集中在明確的composition root。

### 14.2 變更品質

新模組與新邊界有明確型別，公共接口不以任意dict或任意Callable長期代替契約；外部JSON在入口驗證後轉成型別。金錢用Decimal，時鐘可注入，風控與持有政策可離線確定性測試。

每個模組只維持可說明的單一責任。檔案超過約400行或函式超過約60行時列入拆分審查，這是檢視訊號；不能為符合行數任意切碎相同概念。重複的費用、取整、日曆或錯誤映射必須指向同一權威實作。

每次交付附需求及驗收ID、依賴圖變化、資料格式相容策略、測試證據和回退方式。新UI字串沿用既有字串表，錯誤沿用ERROR_TABLE，保留既有objectName及無障礙名稱的相容性。

### 14.3 升級及回退

schema新增先走向後相容的加法遷移；不可逆遷移先備份並驗證回讀。引擎v2結果使用新producer及profile，舊回測和紙上結果保持可讀。回退程式不代表回退券商真實交易，必須先停止新倉並完成對帳。

功能開關只控制已驗收能力的可見性及部署，不能繞過資格、風控或資料驗證。SDK與套件版本鎖定、依賴稽核、合適的lint及測試依照現有CI整合，不放寬既有逾時或以重跑取代根因分析。

替身測試確認內部契約與故障處理；券商模擬確認支援範圍的實際介面；唯讀正式連線確認帳戶與資料；受控正式驗證才確認實際交易路徑。各級不能相互冒充。

正式啟用每一市場、方向及持有政策之前，須完成適用案例、處理所有重大缺陷、確認對帳與人工處理方式，並由使用者在啟動摘要選定實際帳戶及執行範圍。績效驗證不等於未來獲利保證，工程驗收也不自動提高既有正式驗收分數。

## 17 權限開通後的接入清單

第一步在本機安全設定金鑰引用及環境，執行無交易副作用的連線診斷，顯示帳戶、行情、帳務、交易、正式環境及CA各自狀態。[S7][S8]

第二步讀取實際商品與規則，核對張股、口數、月份、時段、成本及保證金版本，保存能力快照。缺少API可查資格欄位時，只能接受可稽核的券商確認及有效期限，不能由畫面勾選自行宣告通過。

第三步對指定帳戶執行行情與帳務查詢，核對持倉、可賣或可平量、交割及委託。第四步進行券商模擬及故障案例，再完成跨日觀察。第五步在正式路徑已獨立實作及驗收後，由使用者選定受控正式驗證範圍。

新增期貨帳戶時重用同一連線設定與交易畫面，只新增帳戶能力、期貨規則及適用測試。若SDK欄位、單位或功能與預期不符，只調整連接器和契約版本；核心仍須執行回歸，不能以「不改核心」為理由跳過驗證。
