# MarkAuto 介面設計準則

Status: ACCEPTED（擁有者 2026-11-01）。適用所有新畫面；既有畫面由 [UX-1 一致性整修](ux1-ui-consistency-spec.md) 逐步套用。
用語與 tooltip 寫法另見 [TERMINOLOGY_AND_TOOLTIP_STYLE.md](../user/TERMINOLOGY_AND_TOOLTIP_STYLE.md)。

## 1. 原則

1. **一眼看懂狀態**：使用者最先需要知道的是「現在在哪個環境、有沒有異常、今天賺賠多少」，放在最顯眼處。
2. **一頁一個主要動作**：主要動作最明顯；危險動作看得出危險；其他動作退居一般。
3. **少字**：每頁一句話說明，細節收進「?」。不在畫面上寫段落。
4. **空的地方告訴下一步**：沒有資料時，說明原因並給一個前往下一步的按鈕。
5. **安全相關一律明確**：正式／模擬、停用原因、異常都用文字講清楚，不只靠顏色。

## 2. 頁面版型

每個主頁面由上到下：

```
標題                                   [?] [主要按鈕]
一句話說明（最多 40 個中文字）
────────────────────────────────────────
重點卡片列（3–5 張，數字為主）           ← 可省略
────────────────────────────────────────
主要內容（表格、圖表或表單）
────────────────────────────────────────
次要內容（收合區塊「進階」）             ← 可省略
```

- 「?」固定在標題右側（沿用 M1-U U10）。
- 長說明、操作步驟、限制條件放「?」或 tooltip，不放頁面本文。
- 錯誤與異常用頁面頂端的單一提示列，不在多處重複。

## 3. 按鈕分級

沿用 [theme.py](../../desktop_app/shell/theme.py) 既有的 `role` 屬性，不新增樣式系統：

| 等級 | `role` | 外觀 | 用途 | 規則 |
|---|---|---|---|---|
| 主要 | `primary` | 藍底白字 | 該頁最主要的下一步（新增策略、儲存並連線、執行回測） | 每頁最多 1 個 |
| 一般 | `secondary` | 框線 | 其他操作 | 預設 |
| 危險 | `danger` | 紅底白字 | 停止、撤單、平倉、刪除、清除 | 按下後必須確認，確認框預設選「取消」 |

- v2 交易版的 `desktop_app/features/trading/widgets.py` `button()` 要能指定 `role`；不得用 inline `setStyleSheet`。
- 停用的按鈕旁邊或 tooltip 要說明「為什麼不能按、要先做什麼」。
- 按鈕文字用動詞開頭、一般使用者看得懂（「停止所有新倉」優於「停止新倉並撤進場單」）；必要的精確說明放 tooltip。

## 4. 狀態與顏色

| 意義 | 顏色 token | 用在 |
|---|---|---|
| 正常、成功、已連線 | `success` | 狀態點、標章 |
| 注意、延遲、等待 | `warning` | 狀態點、提示列 |
| 異常、失敗、需處理 | `danger` | 只用在真正的異常；例行流程（如啟動時的首次對帳）不得用紅色 |
| 中性、資訊 | `neutral` | 例行進行中的狀態 |
| 漲／跌 | 依使用者「漲跌配色」設定 | 價格、損益；不與上列狀態色混用 |

環境識別（M2-6）：本機模擬灰藍、券商模擬綠、正式紅色外框與色帶。環境名稱一律以文字同時標示。

## 5. 頂部列

- 只放常駐資訊：**環境標章、今日損益、待處理數、連線狀態**，各以小標章呈現，點擊可看細節。
- 只有在作業進行中才顯示「取消作業」。
- 不常用的連線（例如 ChatGPT）縮成小圖示加 tooltip。
- 高度不超過 48px（沿用 M1-U U13）。

## 6. 表格

- 預設顯示最重要的 5–6 欄；其餘欄位由表頭右鍵或「欄位」按鈕勾選，選擇記在本機偏好。
- 1366×768 視窗下預設欄位不得出現橫向捲軸。
- 數字靠右對齊、加千分位、固定小數位；金額標示單位；損益依漲跌配色上色；未知值顯示「未知」（灰色）。
- 欄位標題用白話；專業名詞加 tooltip。
- 可排序的欄位點表頭排序。

## 7. 空狀態

表格或區塊沒有資料時，在表格中央顯示：

```
（一句說明為什麼是空的）
[前往下一步的按鈕]
```

例：「還沒有策略。」[新增策略]；「還沒有成交紀錄。策略啟用並下單後會出現在這裡。」

## 8. 回饋與等待

- 超過 0.5 秒的操作顯示進行中狀態，完成後短暫提示結果（沿用既有 `AsyncStatus`）。
- 失敗訊息用 `ERROR_TABLE` 的「發生什麼 + 下一步」兩段式，不顯示例外內容。
- 不用彈出視窗打斷使用者，除非是危險操作的確認或需要立即處理的異常。

## 9. 文字

- 繁體中文、一般投資人用語；英文代碼（例如 `trend`、`LOCAL_SIMULATED`）不得直接顯示。
- 時間一律台北時間，格式 `11/01 13:30`；日期需要年份時用 `2026/11/01`。
- 數字單位：股票「張」、期貨「口」、金額「元」。

## 10. 檢查清單（每個 UI PR 附在說明）

- [ ] 版型符合第 2 節；每頁最多一個主要按鈕；危險操作有確認。
- [ ] 沒有 inline 樣式；新樣式只在 `theme.py`。
- [ ] 空狀態有說明與下一步按鈕。
- [ ] 1366×768 與 1920×1080 截圖，無被截斷文字、無非必要橫向捲軸。
- [ ] 沒有直接顯示的英文代碼或 UTC 時間。
- [ ] 鍵盤可操作、每個控制項有無障礙名稱。
