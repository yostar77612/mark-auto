## 重現與修復

在 repo 隔離目錄以實際 SQLite 3.54.0 對照：普通檔名約 259 字元時建表
失敗 SQLITE_CANTOPEN；600 字元以上的延伸本機檔名可建立與提交。
Python 建立超長目錄亦重現 WinError 206。既有 Path.as_uri 把延伸前綴當成
URI authority，直接套用會失敗；修復改用完整跳脫檔名，保留原開啟模式。

原始四個回歸在修復前均因實際長路徑 I/O 失敗。另補歷史匯入與 UTF-16
邊界案例，均先確認失敗，再修復。Windows 字元數以 UTF-16 計算，包含中文、
空白、百分比、井號及非 BMP 字元。修復不更換 SQLite、VFS、系統登錄或權限。

已確認的反例包含：唯讀連線不得寫入或建立遺失資料庫、別名連線互斥鎖衝突、
備份不得放進工作區、UNC／裝置來源拒絕、Paper 重開仍要求對帳、WFO 已消耗
範圍不得重算、保留集仍排除。24 個歷史 producer profile 不變，僅追加兩個
來源相容 profile；舊、新精確來源組合與混合來源拒絕均有離線驗證。

明示 --smoke-isolated 的長 TEMP 整輪原始碼 smoke 已通過：原工作區讀寫與
known-folder 探索由測試禁止，主要七步、手動匯出／匯入、歷史匯入、WFO
及清理全部完成；沒有新增 ChatGPT 帳號請求。安裝版仍須另驗。

手動匯出均曾回報相同 WinError 5；失敗紀錄保留，沒有加重試或放寬閘門。
部分舊測試因主機缺少建立 symlink 的權限而 WinError 1314；測試未略過。
